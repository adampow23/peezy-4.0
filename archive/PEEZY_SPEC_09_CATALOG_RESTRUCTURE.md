## Architecture Decisions (revised where the audit contradicted; do not revisit)
1. **Nudges are task docs**, generated by TaskGenerationService like any row, status "Upcoming", `tier:"nudge"` field. They render **on Home only** (locked product decision: nudges are opt-in Home cards). Tasks tab and Timeline never show a nudge; they show the spawned real task after a Yes.
2. **Nudge timing:** nudge doc dueDate = spawn target's computed date − `leadDays` (default 2). Spawned task dueDate = the target row's own original rule. Both computed by one shared helper used identically in both generation loops; the nudge row resolves its target via a catalog snapshot indexed by taskId.
3. **Fire broad, card filters:** uncertain conditions fire for the broad category; the card's wording filters. Never skip on uncertainty.
4. **Conversations ride the existing workflow mechanism.** No new routing field: a conversation row is `actionType:"workflow"` with a `workflowId` pointing at its flowDefinitions doc, plus `tier:"conversation"`. TaskFlowRouter and the engine carry it end-to-end.
5. **Engine gains one terminal step kind and one step field** (expressiveness rule — the audit killed the ending-action approach):
   - `kind:"spawn"` — terminal. Renders a confirmation card (spawned task titles + "Scheduled for {date}"), calls the `spawnTasks` callable with collected answers + the spawn list, then `onComplete()`. Spawn list entries support `when` guards (existing branch semantics) and `perSelectionFrom:"stepId"` (one spawn per selected option of a multi-select step — Money Accounts, `titleParams.institution` = option label).
   - `skipIfKnown:"key"` on any step — if the key resolves in known answers, adopt the value and advance (never re-ask).
6. **One spawn callable.** `spawnTasks` (Cloud Function, plain JS, style-matched to existing callables in index.js): validates against `taskCatalog`, writes task docs to `users/{uid}/tasks` **mirroring the generation doc shape with status "Upcoming"** (NOT "pending" — terminal legacy), merges answers to `users/{uid}/moveAnswers/answers`, idempotent via client token, token committed in the same batch.
7. **Answer memory** lives at `users/{uid}/moveAnswers/answers` — written only by `spawnTasks`. Read path: **direct client Firestore read** (a small `MoveAnswersStore`, read at flow launch) under one additive rule: `match /users/{userId}/moveAnswers/{doc} { allow read: if request.auth.uid == userId; }`. No client write rule. `getWorkflowQualifying` is not modified.
8. **Completion spawns:** catalog rows carry `onCompleteSpawns`; generation stamps them onto task docs; mapper decodes onto PeezyCard. One shared `SpawnService.runCompletionSpawns(for:)` called from BOTH completion paths — inside `markTaskCompleted` after the awaited updateData succeeds (:85), and in `TasksStore.markComplete`'s `onSuccess`.
9. **Sequencing is date math** (`dateRule` optional per-row override: `{anchor:"moveDate", offsetDays:N}`; absent = existing urgency math). No dependency engine.
10. **Deletion doctrine (eab4193):** deleted rows retire conditions AND orphaned keys same commit. Deletions mapped against the 47-row HEAD inventory during JSON authoring. BUY_PACKING_SUPPLIES already retired; MOVE_CHECKIN, BOX_RETURN, PACKING_* survive untouched.
11. **New TaskStatus cases** `dismissed = "Dismissed"`, `converted = "Converted"` — terminal. Home query allowlist excludes them (no query change needed). TaskGrouping: both `continue` (skip everywhere, like `.skipped`). Timeline never shows them.
12. **Quote tracking:** v1 = `quotes:[{company,notes}]` on the task doc (client write via TaskActionService). Man-hour normalizer (BOOK_MOVERS, `quoteTracker:"manHours"`) = structured fields + pure client math.
13. **Show the date, always:** "Scheduled for {date}", never bare "scheduled".
14. **Out of scope:** walk-measurement AR, quote-upload analysis, provider email automation, learnings library.

## Phase 6: Man-Hour Normalizer — BOOK_MOVERS (files: 1 modify, 2 create)

**READ FIRST:** `QuoteTrackerView.swift` (Phase 5), BOOK_MOVERS v2 row.

**Order of operations:** `quoteTracker == "manHours"` → tracker swaps the v1 notes-only entry for structured fields per quote (company · crew size · quoted hours · per-man rate · travel fee; notes retained beneath) → normalizer computes → side-by-side table: per-quote total man-hours, fleet average, each company re-priced at the average, lowball flag.

**Create `ManHourNormalizer.swift`** — pure struct, complete code, this is the single source for the formula:

```swift
struct MoverQuote: Codable, Equatable {
    var company: String
    var crew: Int
    var hours: Double
    var perManRate: Double
    var travelFee: Double
}

struct NormalizedQuote: Equatable {
    let company: String
    let totalManHours: Double   // crew × hours
    let repricedTotal: Double   // avgManHours × perManRate + travelFee
    let lowball: Bool           // totalManHours < avg (only when 2+ quotes)
}

enum ManHourNormalizer {
    static func normalize(_ quotes: [MoverQuote]) -> [NormalizedQuote] {
        guard !quotes.isEmpty else { return [] }
        let manHours = quotes.map { Double($0.crew) * $0.hours }
        let avg = manHours.reduce(0, +) / Double(manHours.count)
        return zip(quotes, manHours).map { quote, mh in
            NormalizedQuote(
                company: quote.company,
                totalManHours: mh,
                repricedTotal: avg * quote.perManRate + quote.travelFee,
                lowball: quotes.count > 1 && mh < avg
            )
        }
    }
}
```
